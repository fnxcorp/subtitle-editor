# Subtitle Editor

Edit `.srt` / `.vtt` subtitles in sync with a video, entirely on your computer: local and private,
with no uploads. **Your original file is never modified.** You work on a copy that saves itself, and
export the final file when you're done.

- **Sync**: two-point sync (fixes offset and speed at once), live timing (hold Space while each line
  is spoken), shift, FPS conversion, and a timeline that snaps to the playhead, neighbours and shot changes.
- **Edit**: Enter splits at the cursor, Alt+Enter adds a line break, Del / ⌫ merge blocks, multi-select,
  balance lines, top position, find and replace, loop, frame stepping.
- **Quality**: reading speed, line length, duration, gaps, overlaps and shot changes, with a Review tab
  and one-click fixes.
- **Translate** side by side, **transcribe** with Whisper running locally, **detect shot changes**.
- **Command palette** (Cmd/Ctrl+K), remappable shortcuts, English and Spanish UI, built-in help (F1).

## Quick start

```bash
git clone https://github.com/fnxcorp/subtitle-editor.git
cd subtitle-editor
nvm use              # Node 26 (see .nvmrc)
npm install
npm start            # builds, then serves the browser app at http://localhost:5173 (Chrome or Edge recommended)
npm run app          # desktop app (Electron)
npm run app -- movie.mp4 movie.srt
```

Requirements: Node 26.11+. Written in TypeScript (strict); `npm start` and `npm run app` compile first.

Video formats: whatever the browser plays (MP4 H.264/AAC, WebM, MOV). In the desktop app, MKV and
other formats are converted to MP4 automatically if ffmpeg is installed (`brew install ffmpeg`).

## Project structure

```
src/
  server/server.ts        Local server: serves public/, saves working copies, streams desktop files
  desktop/                Electron wrapper (main process + preload)
  web/                    The app (browser), compiled to public/js/
    main.ts               Entry point: loads the language, then app.ts
    app.ts                Composition root: wires features together, startup and main loop  ← start here
    core/                 Pure logic, no DOM, unit-tested in Node
      types.ts              Shared types: Cue, Issue, VideoSource…
      state.ts              Shared app state (cues, selection, playback, timeline view)
      settings.ts           User preferences (localStorage)
      cues.ts               Cue helpers, history, commit() → 'cues-changed' event
      events.ts             Tiny event bus
      subtitles.ts          SRT / WebVTT parsing and export
      time.ts, text.ts      Timecodes and frames; text helpers
      balance.ts            Line balancing
      i18n.ts               T('key', vars), plurals, loading locales
    ui/                   DOM helpers: $, toast, menus
    features/             One file per feature: list, timeline, playback, editing, files, saving,
                          quality, review, find, sync, live, scenes, transcribe, overlay, waveform,
                          commands (every action + shortcuts), keyboard, palette, settings-dialog, help
    workers/              Whisper Web Worker (Transformers.js)
    dev/test-scope.ts     Exposes module exports to the end-to-end tests (not used by the app)
    globals.d.ts          Types for browser APIs missing from TypeScript's DOM library
public/
  index.html              Markup only; every text comes from locales/ via data-i18n attributes
  locales/en.json, es.json  All UI text, including the help pages
  css/                    Styles split by area (base, layout, list, video, timeline, review, dialogs, help)
  js/                     Generated by the build (git-ignored)
build/                    Generated server, desktop and test code (git-ignored)
test/
  unit.test.mts           npm test: core modules, run straight from TypeScript by Node
  e2e.ts                  npm run test:e2e: the whole app in a real Electron window
```

### How it fits together

1. A feature changes `state.cues` between `pushHistory()` (for undo) and `commit()`.
2. `commit()` emits `cues-changed`. `app.ts` reacts in one place: it re-renders the list, overlay,
   timeline, review and find, and saves the working copy.
3. Every user action is a command in `features/commands.ts`, so shortcuts, the palette and the help
   all come from one list.

## Scripts

```bash
npm run build                              # compile src/ → public/js/ and build/
npm run check                              # type-check + lint + unit tests (run before every commit)
npm run lint                               # ESLint with typescript-eslint
npm test                                   # unit tests
npm run test:e2e                           # end-to-end (opens a window briefly)
CLIP=/path/video.mp4 npm run test:e2e      # also runs the video tests (waveform, cuts, fps, live timing)
WHISPER=1 CLIP=/path/video.mp4 npm run test:e2e   # also runs a real transcription (downloads ~40 MB once)
npm run dist                               # package the desktop app (.dmg / .exe)
```

A good test clip with shot changes, speech and audio: <https://media.w3.org/2010/05/sintel/trailer.mp4>

## Saving

Every change goes to `working-copies/<name>.working-copy.srt`, plus a snapshot in `history/` every
5 minutes, and to the browser's storage. Use **Export ▾** for the final SRT / WebVTT.

## Languages

English and Spanish (⚙ Settings → Language). To add a language, copy `public/locales/en.json`,
translate it and add its code to `LANGS` in `src/web/core/i18n.ts`.
